# WS3 Shared Execution Contract

## Shared approved invariants

Approved Phase 2 B6–B14, Domain G, and Phase 3 WS5/WS7–WS10 control this
contract. Project boundaries remain default; unauthorized cross-Project Context
does not become observed, represented, applicable, or selected. Requester
authorization and Consumer disclosure are distinct. Authority Scope, Authority,
and Governance State remain independent; representation, selection, packaging,
rendering, repetition, persistence, or retrieval do not amplify Authority.

Historical/restored state does not become current, authorized, governing, or
presently disclosable by persistence alone. Provenance and security-relevant
audit remain attributable and authorization-bound without duplicating protected
content. Source-derived imperative content remains evidence/content unless
independently established governance applies. Required Context, Conflict,
Uncertainty, material limitations, qualification, sufficiency, and
package/rendering boundaries remain explicit: denial must not become false
absence, false success, invented disclosure, invented access, or invented
Authority.

## Result, evidence, and provenance

WS1 controls PASS, FAIL, INDETERMINATE, Finding, H3, remediation, and
supersession. Each deliberate execution must preserve, as applicable: exact
branch and common baseline; lane-private control identity/version; fixture/input
identities and hashes; application baseline; environment; isolation/state setup;
raw procedure; stdout/stderr; raw result; relevant state; package/manifest and
renderers when applicable; audit/Provenance artifacts when applicable; ER
comparison; result/Finding linkage; and SHA-256 manifest. Irrelevant artifacts
need not be manufactured.

Historical provenance is distinct from current control/record integrity. Use the
immutable Git baseline, lane-private file hashes, deterministic record-level
hashes where shared records are referenced, and explicit historical lineage.
Do not treat append-only shared registers as whole-file byte-identical controls.

Once executed, a control is immutable. Preserve an erroneous control and its
result; investigate and obtain Owner disposition; then create a superseding
version and separate successor evidence. Never edit an executed ER merely to
obtain PASS or convert predecessor FAIL/INDETERMINATE into PASS.

## Ownership, freeze, and authority

Lane A owns docs/phase-4/ws3-lane-a-crossing-disclosure and evidence IDs
VE-P4-3A-*. Lane B owns docs/phase-4/ws3-lane-b-trust-state-audit and
VE-P4-3B-*. Lane C owns docs/phase-4/ws3-lane-c-inert-preservation and
VE-P4-3C-*. Lane-private fixtures/ERs/controls/results/findings belong only in
the owning namespace.

Read-only during parallel work: AGENTS.md, README.md, roadmap, checklist, WS1
package/registers, WS2 evidence/dispositions/closure, DVL, this package,
source, tests, pyproject.toml, existing evidence/findings, and every other lane
directory. A requested frozen-file change is an integration dependency and
requires stop.

After worktree creation and a lane-specific authorization, a lane may proceed
analysis -> lane-private control/fixture/ER -> freeze -> preflight -> execution
-> evidence -> PASS classification -> bounded post-results analysis. It may not
remediate, revise executed controls, create accepted limitations, make material
policy/architecture decisions, invalidate prior evidence, complete Item 3.9,
close WS3, approve Gate 4B, authorize proving, or establish readiness.

## Stop and context rules

Stop and preserve on FAIL, INDETERMINATE, H3, new MATERIAL Finding, ambiguity,
governance conflict, unintegrated-lane dependency, frozen-file change,
source/test remediation need, architecture/technology/security-policy decision,
prior-evidence invalidation, accepted-limitation decision, TD-14 threshold, or
Gate/proving/readiness question. Faithful PASS, unchanged controls, evidence
preservation, and bounded no-decision analysis may continue automatically.

Core context: AGENTS.md; WS3 topology; this package; WS1 result/Finding/H3
rules; WS2 closure/DVL/TD-14 state; and exact lane obligations. Lane A adds
Phase 2 B7–B8, Phase 3 WS4/WS7, and F5-A. Lane B adds Phase 2 B6/B9/B13–B14/
Domain G and Phase 3 WS5/WS7/WS10. Lane C adds Phase 2 B11–B12/E/F and Phase 3
