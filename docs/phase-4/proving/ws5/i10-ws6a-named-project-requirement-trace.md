## Conclusion

The current named-project dependency is governing, not a later Codex implementation choice.  It first appears in the original approved Phase 0 definition: Phase 0 §15 says, exactly, **“The Company AI Roadmap is the first external proving ground. Context Engine itself is the dogfooding case.”**  Phase 0 §14(9) separately requires a fresh ChatGPT session to use an **AI Roadmap** package for meaningful continuation with substantially less manual reconstruction.  Phase 1 Item 53 and Phase 2 I10 retain and make that selection operational.

Consequently, replacing the named Project with an eligible-but-unnamed external Project is **not** an interpretation, a Phase 2 architecture change, or a mere WS5.5/WS6A protocol clarification.  It is **E — a governed baseline amendment spanning the Phase 0 proving-ground/success-criterion decision, the Phase 1 requirement, Phase 2 I10 plan, and Phase 4 execution records.**  It may preserve the general external-project proving *properties*, but it does not preserve the current expressly named proving claim without an Owner-approved supersession/amendment.

The recent external-project execution analysis is therefore correctly limited to a conditional recommendation for the then-named Company AI Roadmap target.  The Project Owner’s clarification that Context Engine itself needs no employer/company authorization removes that assumption for a future independent personal Project; it does not retrospectively change the governing target or authorize a replacement.

## 2. WS6A origin and meaning

The governing WS6A text is the [Phase 4 checklist](../../../checklists/checklist-phase-4-validation-integration.md):

> **WS6A — Company AI Roadmap External Proving**  
> **Purpose:** Determine whether v0.1 can provide governed useful context to a genuinely fresh Consumer for a real project other than Context Engine.

Its 6A.1–6A.5 controls require, respectively: pre-run freshness and frozen protocol/Sources/inputs/task/criteria/evaluator; controlled construction and preserved package/manifest/rendering/delivery boundary; preserved Consumer/intervention/governance/provenance/sufficiency/limitation evidence; immutable original evidence and independent evaluation including reconstruction burden where applicable; and preservation of adverse/invalid evidence without repair folded into PASS.

WS6A therefore requires a real Project and an external Project (a Project other than Context Engine).  Its purpose sentence does not itself say that any qualifying external Project may be substituted: its heading and the upstream Phase 0/1/I10 records name Company AI Roadmap.  The later `ws6a-context-manifest.md`, WS5.5 records, and authorization package are execution manifestations of that inherited choice, not an independent authorization to select another Project.

## 3. Material external-project properties

The approved records support these intended properties:

- A real Git Project with non-synthetic, governed Source material (Phase 0 §14(1), §15; Phase 1 Item 53; I10).
- Independence from Context Engine, so the external case complements rather than substitutes for dogfooding (Phase 0 §15–16; I10/I11; WS6A/WS6B sequence).
- A real task with authentic Project identity, purpose, authority, status/current work, constraints, unresolved items, Source state, and usable Provenance (I10; Phase 1 Item 53).
- Actual current/historical/superseded, Candidate/proposal, missing/unavailable/uncertain, isolation, and adversarial-content conditions where applicable (I10 P1–P8; Phase 1 Item 53).
- A fair comparison against ordinary minimal pointer/access and measurable manual reconstruction burden, not a synthetic recall test or arbitrary token target (Phase 0 §14(9); I10).
- General mechanism rather than Project-name-specific core behavior (Phase 0 §15; Phase 1 Item 53; I10 hard failure).

These properties explain why a fictional fixture is not currently adequate: it is not the named real Project and can encode its own expected patterns.  They do **not** prove that Company AI Roadmap’s particular subject matter, employer affiliation, or location is semantically necessary to the general external-project capability claim.  Those features are not identified as acceptance properties in the approved records.  The Project name remains material because it was expressly selected as the first proving ground.

## 5. Amendment classification and narrowest possible formulation

No project-neutral reading can be adopted as a clarification: the unambiguous original words select Company AI Roadmap, and Phase 1/I10 repeat it.  Nor is it solely a proving-protocol amendment, because the named proving ground and AI Roadmap package occur in Phase 0 success criteria and Phase 1 requirements.  It is not a Phase 2 architecture choice; architecture preserved the already-selected target.

The narrowest compatible **candidate** replacement, if the Owner elects to amend the baseline, is:

> **The first external proving ground shall be one real, independently maintained Project other than Context Engine, selected separately by the Project Owner before source observation or Consumer exposure.  It shall satisfy the approved external-project proving criteria and shall be used for the same fresh-Consumer governed-continuation, fair-control, reconstruction-burden, evidence-preservation, and independent-evaluation claim.  Synthetic fixtures and a Project created or materially shaped to produce the proving result do not qualify.**

This is deliberately a candidate formulation, not an adopted requirement.  It is narrower than “any external Project” because it preserves reality, independent maintenance, externality, the generality guard, and separate Owner selection.  It must be harmonized across Phase 0 §14(9)/§15, Phase 1 Item 53, I10/I4/G12, the WS6A heading/records, and any traceability/exit-gate wording.  The Owner must decide whether the Phase 0 phrase “AI Roadmap package” becomes “qualifying external-Project package”; leaving that phrase unchanged would conflict with project neutrality.

## 6. Invariants a later amendment must retain

The following are non-negotiable for preserving proving strength:

- a real Project, independent of Context Engine, with non-synthetic pre-existing history/Sources and no proving-tailored corpus;
- governed Bootstrap/configuration, authoritative/provenance-bearing Sources, bounded task-relative ASU, observed states, and Consumer disclosure authorization;
- a real, meaningful continuation task exercising identity, status, authority/authorization, current/historical/superseded and Candidate distinctions, limitations/uncertainty, Source-as-evidence, isolation, and applicable P1–P8 conditions;
- applicability, sufficiency, limitations, conflicts/gaps, and honest qualified/insufficient outcomes rather than forced answers;

- a genuinely fresh package Consumer; a separate genuinely fresh control Consumer; separate package/control arms; exact-run controls; predetermined criteria; raw original-output preservation; and independent evaluation;
- fair ordinary minimal pointer/access control, same task, and a reconstruction-burden comparison using I10’s documented measures;
- no project-specific core logic, no source/test/dependency/remediation scope expansion, and no conclusion beyond the evidence-bounded external-project claim.
