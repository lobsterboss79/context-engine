# Proving Protocol and Evidence Architecture Template

**Template status:** Future-use architecture only. Proving remains unauthorized pending Gate 4B PASS and applicable authorization.

## Controlling sequence

`freeze protocol and criteria -> establish exact-run Consumer freshness -> freeze/preserve package and rendering -> Consumer interaction -> freeze/preserve original outcome -> independent evaluation -> Gate 4C evidence acceptance/rejection -> only then governed remediation where applicable`

## Future proving-run record

| Layer | Required future record |
| --- | --- |
| Pre-run state | Proving Run ID; exact baseline; task/request; controlled/permitted Sources; frozen protocol and criteria; permitted Consumer inputs; known limitations; Consumer/session boundary; preflight result; authorization; environment/configuration. |
| Constructed evidence | Exact logical Context Package; Source Manifest/construction evidence; material Provenance, Conflict, Uncertainty, limitations, sufficiency, Construction-State Coherence; frozen Consumer-facing rendering; delivery boundary. |
| Consumer interaction evidence | What was delivered; response/output; questions; interventions; added information and supplier; outcome; continuation/inability evidence; material omissions/inappropriate inclusions/reconstruction burden. |
| Original-outcome preservation | Immutable original artifacts and timestamped lineage before explanation, repair, coaching, or reinterpretation. |
| Evaluation evidence | Independent evaluator/reviewer identity and role; frozen criteria; assessment of frozen original evidence; supported/unsupported conclusions; qualifications; findings; result state; recommendation/disposition. |

Logical package, rendering, delivery, receipt, and use remain distinct. Evaluation must not alter the package/rendering, supply missing context, repair the system, coach the Consumer, or change criteria after outcome observation and then grade the altered result.

## Valid failure and invalid-run control

`VALID FAIL != INVALID RUN`

| Condition | Required handling |
| --- | --- |
| Valid FAIL | Preserve as evidence about the system; record finding/disposition as applicable. |
| Invalid run: freshness FAIL/INDETERMINATE, material protocol change/breach, unauthorized context/manual assistance, unpreserved original evidence, wrong material baseline/configuration/Bootstrap, or material uncontrolled event | Preserve original evidence; mark **INVALID**; record invalidation reason and protocol/finding evidence; exclude from proving-success claims; only later restart under valid frozen protocol with fresh suitable Consumer if authorized. |

Never convert an invalid run to PASS or FAIL for convenience, retroactively repair the protocol, or erase evidence of invalidation. Gate 4C accepts or rejects proving evidence; independent evaluation does not grant material decision authority.
